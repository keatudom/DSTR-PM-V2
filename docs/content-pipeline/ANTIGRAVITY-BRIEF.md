## 2. กติกาบังคับของระบบ (ห้ามแหก — เพิ่งแก้ปัญหาพวกนี้ไปวันนี้)

1. **ใช้ `css/design-system.css` เท่านั้น** — ห้ามสร้าง design token ใหม่ · **ไม่มีเฉดสี `-600` ของ success/warning/error** (ใช้แล้วปุ่มจะโปร่งใสมองไม่เห็น) ใช้ `-50` / `-500` / `-700`
2. **เมนูวาดโดย `js/shell.js`** — เรียก `Shell.render({ page:'content', title:'...', scope:'project' })` ห้ามเขียน sidebar/แถบล่างเอง
   - โครงหน้าต้องเป็น `<div class="app-container"><main class="main-content"><div class="page-content">…</div></main></div>`
   - ถ้าจะเพิ่มเมนู ให้เพิ่มใน `NAV.project` ของ `shell.js` (มี `label` = เมนูข้าง + `short` = แถบล่าง) **ห้ามนิยามแถบล่างแยก**
3. **ห้ามใช้คำว่า "ภาพรวม" เป็นชื่อเมนู/แท็บระดับบน** — ชนกับแท็บ "ภาพรวม" ในหน้าโครงการ
4. **มือถือ ≤768px:** ปุ่ม/ช่องกรอกสูง ≥44px · แถบที่เลื่อนแนวนอนต้องซ่อน scrollbar (มี util ใน design-system แล้ว) · **ห้ามให้หน้าเลื่อนซ้าย-ขวา**
5. **ห้าม hardcode `bow-house`** ใช้ `state.projectId` ทุกที่
6. **ไอคอน Lucide เท่านั้น** (`vendor/lucide/lucide.min.js` self-host) ห้ามใช้ CDN · อีโมจิใช้ได้เฉพาะข้อความที่มาจากฐานข้อมูล
7. แก้ CSS/JS แล้ว **ต้องบวกเลข `CACHE` ใน `sw.js`** ไม่งั้น PWA ของช่างเห็นของเก่า

## 3. หน้านี้ต้องทำอะไร (สถานี 2-4 ของกลยุทธ์)

> สเปกจากกลยุทธ์ (ส่วนที่ใช้พัฒนา): [`PIPELINE-SPEC.md`](./PIPELINE-SPEC.md)

**เรื่องราว:** โฟร์แมนบันทึกงาน + ถ่ายรูปทุกวันอยู่แล้ว (ของจริง: บันทึก ~10.5/วัน · รูป ~2.8/วัน)
ของพวกนี้ไปไม่ถึงเพจ หน้านี้คือสายพานที่พาไป — คนใช้เวลาแค่ **จันทร์ละ 30 นาที เคาะ 3 ชิ้น**

### จอที่ต้องมี 3 จอ (จะทำเป็นแท็บหรือขั้นตอนก็ได้ — Antigravity ออกแบบ)

**จอ A · เลือกวัตถุดิบ**
- ดึงจาก `API.getContentCandidates({source, from, to, ff_code, q})`
- แสดงเป็นตารางรูปคล้าย `/gallery.html` + ติ๊กเลือกได้หลายชิ้น (**สูงสุด 10 ชิ้น/ครั้ง**)
- แต่ละชิ้นมี: รูป · วันที่ · รหัส+ชื่อชิ้นงาน · **ข้อความที่ช่างพิมพ์ไว้จริง** (สำคัญ ต้องอ่านออกง่าย เพราะคนใช้ตรงนี้ตัดสินใจ)
- ชิปกรองแหล่ง: รายงานประจำวัน / หลักฐานงาน / เช็คอิน / QC
  → **ค่าเริ่มต้นแนะนำ: รายงานประจำวัน + หลักฐานงาน** (เช็คอินส่วนใหญ่เป็นรูปยืนยันตัวคน ใช้ทำ marketing ไม่ค่อยได้)
- เลือกสไตล์ (5 แบบ) + ปลายทาง (fb/ig/tiktok/line) → ปุ่ม **"ให้ AI เขียนให้"**
- ⚠️ **ปุ่มนี้เสียเงินทุกครั้งที่กด** — ต้องออกแบบให้กดพลาดยาก + บอกจำนวนชิ้นที่จะเขียนก่อนยืนยัน

**จอ B · เคาะ (จอหลักที่ใช้บ่อยสุด)**
- ทีละชิ้น: รูปใหญ่ + แคปชั่นที่ AI เขียน + แฮชแท็ก
- ปุ่ม: **ผ่าน** / **ตก** / **รีแคปชั่น**
  - กติกาจากกลยุทธ์: **ปุ่มรีรูป กับ รีแคปชั่น ต้องแยกกัน** (ถ้าแคปชั่นดีแล้วไม่ต้องเสียเงินเขียนใหม่)
  - เวลากด "รี" ต้อง**บังคับให้พิมพ์เหตุผลสั้นๆ** + มีปุ่มลัดที่ใช้บ่อย: `สั้นลง` `เน้นวัสดุ` `ให้ความรู้มากขึ้น` `อย่าใช้อีโมจิ` `โทนอบอุ่นขึ้น` `ไม่เอารูปติดคน`
  - เหตุผลที่พิมพ์จะถูกเก็บเป็น "คู่มือเสียงแบรนด์" อัตโนมัติ → **ควรมีจุดโชว์ให้เห็นว่าระบบเรียนรู้อะไรไปแล้วบ้าง** (พิสูจน์แล้วว่าใช้ได้จริง: สอนครั้งเดียวว่า "ห้ามใช้ศัพท์ F-XX" ชิ้นถัดไปเลิกใช้เอง)
- แก้แคปชั่นเองได้ในจอ (พิมพ์ทับ)
- ผ่านแล้ว → เลือกปลายทาง + ตั้งเวลา

**จอ C · คิว + ถังสำรอง**
- `API.contentStats()` คืน: จำนวนแต่ละสถานะ · **ถังสำรอง (approved+scheduled) เทียบเป้า 6 ชิ้น** · สัดส่วนสไตล์จริง vs เป้า
- **กติกาเหล็กจากกลยุทธ์: ห้ามเริ่มปล่อยจนกว่าถังสำรองจะครบ 6 ชิ้น** → ต้องโชว์ให้เห็นชัดเป็นตัวหลัก ไม่ใช่ตัวเลขเล็กๆ มุมจอ
- **ปลั๊ก A (ใช้วันแรกได้เลย ไม่ต้องรอ API ของ Meta):** ปุ่ม **"คัดลอกแคปชั่น"** + **"ดาวน์โหลดรูป"** แล้วให้คนเอาไปแปะเอง (~20 วินาที) · กดแล้วมีปุ่ม **"ลงแล้ว"** เพื่อบันทึกสถานะ

### ⭐ 2 เรื่องที่เจ้าของงานเคาะเอง — ห้ามออกแบบสวนทาง
1. **"รูปไม่ต้องสวยเสมอ"** — รูปรายงานของโฟร์แมนใช้เป็นวัตถุดิบได้เลย ระบบ**ไม่มี**ด่านตัดรูปไม่สวยทิ้ง หน้าที่ของ UI คือ *เรียงของมาให้คนเลือกง่าย* ไม่ใช่ตัดสินแทนคน
2. **สิทธิ์ใช้ภาพ** — ถ้าโครงการยังไม่ติ๊กยินยอม API จะคืน `blocked:true` → ต้องมี**หน้าจอกั้นที่อธิบายชัด** + ปุ่มให้ผู้มีสิทธิ์ติ๊ก (`API.setPhotoConsent(true)`) ห้ามข้ามด่านนี้

## 4. API ที่เรียกได้ (มีจริงบน production แล้ว — ทดสอบผ่านหมด)

ทุกตัวอยู่ใน `js/api.js` แนบ `project_id` + token ให้อัตโนมัติ

| เมธอด | ทำอะไร | หมายเหตุ |
|---|---|---|
| `API.getContentCandidates({source, from, to, ff_code, q})` | วัตถุดิบที่ยังไม่เคยหยิบ | คืน `blocked:true` ถ้ายังไม่ยินยอมใช้ภาพ |
| `API.generateContent({items, style, platform})` | AI เขียนแคปชั่น | 💰 เสียเงิน · ≤10 ชิ้น/ครั้ง |
| `API.listContent({status})` | คิวคอนเทนต์ | |
| `API.updateContent({content_id, status, caption, platform, scheduled_at, notes})` | เคาะ/แก้ | status: `draft`→`approved`/`rejected`/`scheduled`/`posted` |
| `API.rerollContent({content_id, note})` | รีเขียนใหม่ + สอนระบบ | 💰 เสียเงิน · `note` = คำสั่งที่จะถูกจำ |
| `API.getBrandVoice()` | กฎที่ระบบเรียนรู้มาแล้ว | เอาไปโชว์ในจอ B |
| `API.setPhotoConsent(true/false)` | ติ๊กยินยอมใช้ภาพ | เฉพาะ owner/director/pm |
| `API.contentStats()` | ถังสำรอง + สัดส่วนสไตล์ + สถานะยินยอม | |

**5 สไตล์** (`style`): `behind` เบื้องหลังงานช่าง 40% · `educate` รู้ไว้ก่อนทำบิ้วอิน 25% · `showcase` เห็นแล้วอยากได้ 20% · `pro` ช่างคุยกับช่าง 10% · `developer` ส่งงานตรงเวลา 5%

**ตัวอย่างผลลัพธ์จริงที่ระบบเขียนออกมา** (สไตล์ behind → fb):
> วันนี้ทีมช่าง DSTR เข้าหน้างานที่ Zone 4 ครับ กำลังเก็บรายละเอียดงานตู้เสื้อผ้าห้องนอนคุณแม่ให้เรียบร้อยทุกจุดเลยครับ งานบิ้วอินต้องใส่ใจทุกขั้นตอนจริงๆ ครับ

## 6. ส่งงานยังไง

1. สร้าง `content.html` ที่ **root** (ไม่ใช่ใน `v3/`) — asset อ้างแบบ `css/…` `js/…` ไม่มี `../`
2. เพิ่มเมนูใน `js/shell.js` → `NAV.project` (`key:'content'`, `label:'โรงงานคอนเทนต์'`, `short:'คอนเทนต์'`, `icon:'megaphone'`)
3. บวกเลข `CACHE` ใน `sw.js`
4. เช็กก่อนส่ง: `grep '\.\./' content.html` ต้องว่าง · เปิดที่ 390px แล้วไม่มีแถบเลื่อนแนวนอน · console ไม่มี error
