## 2. กติกาบังคับของระบบ (ห้ามแหก)

1. **ใช้ `css/design-system.css` เท่านั้น** ห้ามสร้าง design token ใหม่
   ⚠️ **ไม่มีเฉดสี `-600` ของ success/warning/error** (ใช้แล้วปุ่มจะโปร่งใสมองไม่เห็น) มีแค่ `-50` / `-500` / `-700`
2. **เมนูวาดโดย `js/shell.js`** เรียก `Shell.render({ page:'tour', title:'เดินดูหน้างาน', scope:'project' })`
   - โครงหน้า: `<div class="app-container"><main class="main-content"><div class="page-content">…</div></main></div>`
   - เพิ่มเมนูใน `NAV.project` ของ `shell.js` (`label` = เมนูข้าง, `short` = แถบล่าง) **ห้ามนิยามแถบล่างแยก**
   - กติกา "1 หน้า 1 ชื่อ" — ชื่อในเมนูข้างกับแถบล่างต้องสื่อถึงของเดียวกัน
3. **ห้าม hardcode `bow-house`** ใช้ `state.projectId` ทุกที่
4. **ไอคอน Lucide เท่านั้น** (`vendor/lucide/` self-host) **ห้าม CDN ทุกกรณี**
5. **มือถือ ≤768px:** ปุ่ม/ช่องกรอกสูง ≥44px · แถบเลื่อนแนวนอนต้องซ่อน scrollbar · **ห้ามให้หน้าเลื่อนซ้าย-ขวา**
6. แก้ CSS/JS แล้ว **ต้องบวกเลข `CACHE` ใน `sw.js`** (ตอนนี้ `dstr-v6`) ไม่งั้น PWA ของช่างเห็นของเก่า
7. **ตัวเล่นภาพ 360 ใช้ Pannellum** วางไว้ `vendor/pannellum/` — โหลดจากเครื่องเรา ห้าม CDN
8. ⚠️ **`Modal.close()` แล้วเรียก `show()` ทันทีในจังหวะเดียวกัน = modal ใหม่หาย** (timer เคลียร์ 200ms) อย่าปิดซ้ำ
9. ห้ามใช้คำว่า **"ก่อสร้าง"** (ธุรกิจนี้คืองานบิ้วอิน) และห้ามใช้ **"ภาพรวม"** เป็นชื่อแท็บระดับบน (ชนของเดิม)

## 3. หน้านี้ต้องทำอะไร — 3 โหมด

> อ่านตรรกะเต็ม + ชื่อตาราง + สัญญา API ที่ [`TOUR-SPEC.md`](./TOUR-SPEC.md) **ก่อนออกแบบ**

### 🚶 โหมด "ดู" — ใช้บ่อยที่สุด ออกแบบให้ดีที่สุด

องค์ประกอบที่ต้องมีครบ (ตำแหน่ง/หน้าตาแล้วแต่ Antigravity):
- **ภาพพาโน/360 เต็มจอ** ลากนิ้วส่ายได้ · บีบซูมได้
- **ลูกศรเดิน** ลอยอยู่ในภาพตามทิศจริง แตะแล้วกระโดดไปจุดถัดไป (แบบ Google Street View)
- **แถบเลือกเวอร์ชัน** โชว์ **ชื่อเวอร์ชัน + วันที่** เสมอ · แตะแล้วเลือกเวอร์ชันอื่นได้
- **แผนผังจิ๋ว** มุมจอ เห็นว่าตอนนี้ยืนอยู่ตรงไหน · แตะหมุดเพื่อกระโดดข้ามห้อง · ย่อ/ขยายได้
- **ชื่อจุดปัจจุบัน**
- **ป้ายเตือนเมื่อกำลังดูภาพสำรอง** ("ห้องนี้ยังไม่ถ่ายในเวอร์ชันนี้ — กำลังแสดงภาพจาก 'หลังโพรเทค' 5 ส.ค. 69")
- ทางเข้าโหมด **เทียบ 2 เวอร์ชัน** (ม่านเลื่อนกลางจอ ลากซ้าย-ขวา)
- หมุดคอมเมนต์บนภาพ (แตะดู/แตะเพิ่ม)

### 📸 โหมด "ถ่ายเวอร์ชันใหม่" — มือถือล้วน ต้องเร็วและโง่ที่สุด

- เช็คลิสต์จุดที่ต้องถ่าย เห็นชัดว่า **ถ่ายแล้วกี่จาก กี่จุด**
- ⚠️ **ปุ่มถ่ายต้องเปิด "คลังภาพ" ไม่ใช่เปิดกล้องผ่านเว็บ**
  เหตุผล: กล้องที่เปิดจากหน้าเว็บ (`capture`) **ไม่มีโหมดพาโนรามา** ให้เลือก ถ้าใช้ทางนั้นพนักงานถ่ายพาโนไม่ได้เลย
  ขั้นตอนจริง: เดินถ่ายพาโนด้วยแอปกล้องปกติให้ครบ → เข้าแอป → **เลือกทีเดียวหลายรูป → จับคู่กับจุด** (ระบบเดาลำดับให้จากเวลาถ่ายในไฟล์)
- ตอนสร้างเวอร์ชันใหม่ **ระบบเสนอชื่อให้ก่อน** (เช่น "งานติดตั้ง 34% – 18 ส.ค. 69") + ปุ่มลัดคำที่ใช้บ่อย: `ก่อนโพรเทค` `หลังโพรเทค` `ก่อนส่งมอบ` — พนักงานแค่แตะ ไม่ต้องคิดชื่อ
- ปุ่ม **"เผยแพร่"** ชัดเจน (ก่อนกด = เห็นเฉพาะคนถ่าย)

### 🗺️ โหมด "วางแผนที่จุด" — ทำครั้งเดียวตอนเปิดโครงการ (~15 นาที)

- อัปแปลนพื้น → แตะวางหมุด ตั้งชื่อจุด → เปิดภาพจุดนั้น แตะตรงทางเดินเพื่อวางลูกศร
- **โค้ดชุดเดียว ใช้ได้ทั้งคอมและมือถือ** (คอม = ลากด้วยเมาส์ · มือถือ = แตะวาง) **ห้ามแยกเป็น 2 หน้า**

## 4. สิ่งที่เจ้าของงานเคาะแล้ว — ห้ามเปลี่ยน

1. ❌ **ไม่เอาแถบเลื่อนเวลา (time slider)** — เคยเสนอแล้วเจ้าของงานปัดตก บอกว่า "ดูแปลกๆ"
   ✅ ใช้ **ตัวเลือกเวอร์ชัน** แทน — ทุกเวอร์ชันมีชื่อของมันเองอยู่แล้ว
2. ✅ ทุกเวอร์ชันต้องโชว์ **ชื่อ + วันที่** เสมอ ทุกที่ที่มันปรากฏ
3. ✅ เข้าหน้ามา = **เวอร์ชันล่าสุดที่เผยแพร่แล้วเสมอ** ไม่ต้องให้ผู้ใช้เลือกก่อน
4. ✅ เปลี่ยนเวอร์ชันแล้ว **ต้องยืนอยู่ห้องเดิม** ห้ามเด้งกลับจุดแรก
5. ✅ ของเก่าไม่มีวันหาย — ต้องสื่อสารเรื่องนี้ให้ผู้ใช้รู้สึกปลอดภัยผ่านหน้าตาด้วย
6. ✅ ใช้คำว่า **"เวอร์ชัน"** ไม่ใช่ "รอบสแกน"
7. ✅ เฟส 1 **ภายในเท่านั้น** ยังไม่เปิดให้เจ้าบ้าน (แต่ในข้อมูลมีช่อง `visibility` เตรียมไว้แล้ว)

## 5. สิ่งที่ Antigravity มีอิสระเต็มที่ (นี่คือเหตุผลที่เจ้าของงานเรียกคุณมา)

- **สีและอารมณ์ของหน้านี้** — ให้แมตช์กับแพลตฟอร์มเดิม แต่หน้านี้เป็นหน้า "ดูภาพเต็มจอ" หน้าเดียวในระบบ อาจต้องมีภาษาของตัวเอง (เช่น โทนเข้มเพื่อให้ภาพเด่น) — **ตัดสินใจเองได้ แต่ต้องอธิบายเหตุผล**
- **ผังหน้าจอทั้งหมด** ว่าอะไรอยู่ตรงไหน แท็บหรือขั้นตอน
- **หน้าตาลูกศรเดิน** ให้เห็นชัดกลางแดด แต่ไม่บังภาพ
- **การเคลื่อนไหว/จังหวะเปลี่ยนฉาก** ตอนกดลูกศร (ต้องรู้สึกว่า "เดินไป" ไม่ใช่ "ภาพกระตุก")
- **หน้าตาแผนผังจิ๋ว** และวิธีย่อ/ขยาย
- **หน้าตาตัวเลือกเวอร์ชัน** (dropdown / bottom sheet / อย่างอื่น)
- **micro-interaction** ทั้งหมด

## 6. ข้อกำหนดเฉพาะ "คนใช้หน้างานจริง" (สำคัญมาก — อย่ามองข้าม)

| สภาพจริง | ต้องออกแบบยังไง |
|---|---|
| ยืนกลางแดด จอสู้แสงไม่ไหว | คอนทราสต์สูง ตัวหนังสือใหญ่ ปุ่มสำคัญไม่ใช่สีจาง |
| มือเดียว (อีกมือถือของ) | ปุ่มหลักอยู่ **ครึ่งล่างของจอ** เอื้อมนิ้วโป้งถึง |
| นิ้วเปื้อนฝุ่น/เหงื่อ | เป้ากด ≥44px ทุกอัน · เว้นระยะห่างพอ ไม่กดพลาด |
| เน็ตหน้างานช้า/หลุด | โหลดภาพทีละใบตามที่เดินไปถึง ไม่โหลดรวดเดียว · มีสถานะ "กำลังโหลด" ที่ไม่ทำให้คนคิดว่าแอปค้าง · อัปไม่สำเร็จต้องลองใหม่ได้โดยไม่เสียของ |
| เหนื่อยมากอยู่แล้ว | จำนวนการกดต่อ 1 เวอร์ชัน **ต้องน้อยที่สุดเท่าที่จะทำได้** ทุกการกดที่เพิ่มมาต้องมีเหตุผล |

## 7. ส่งมอบอะไร

1. `tour.html` (+ `js/tour.js` ถ้าแยกแล้วอ่านง่ายกว่า) ทำงานได้จริงด้วยข้อมูลจำลอง
2. เพิ่มเมนูใน `js/shell.js` + บวกเลข `CACHE` ใน `sw.js`
3. **ชั้นข้อมูลจำลองแยกก้อนชัดเจน** (เช่น `const TOUR_MOCK = {...}`) — ให้ถอดออกแล้วเสียบ API จริงได้ทันที และ **ชื่อฟิลด์ต้องตรงกับ `TOUR-SPEC.md` เป๊ะ**
4. รูปตัวอย่างพาโน 2-3 ใบสำหรับทดสอบ (หาเองได้ ขอให้เป็นภาพที่ใช้ได้ตามสิทธิ์)
5. บันทึกสั้นๆ ว่า **ตัดสินใจออกแบบอะไร เพราะอะไร** โดยเฉพาะเรื่องสีและผังหน้าจอ
6. ถ้าเจอว่าสเปกมีช่องโหว่ → **เขียนบอก อย่าแก้สเปกเอง**
