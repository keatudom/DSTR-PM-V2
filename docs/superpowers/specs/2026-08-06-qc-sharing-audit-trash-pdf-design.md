# QC — เห็นร่วมกัน / รู้ว่าใครทำ / ถังขยะ 30 วัน / ออก PDF

วันที่: 2026-08-06 · เจ้าของงาน: keatudom (Design Theria) · สถานะ: อนุมัติแล้ว รอลงมือ

## ปัญหาที่เจอจากการใช้งานจริง

เวียงชัยตรวจ QC ของ F-21 / F-22 บนเว็บ live (`https://keatudom.github.io/DSTR-PM-V2/`)
เจ้าของงานเปิดหน้า QC แล้วเจอปัญหา 5 อย่าง:

1. **ไม่เห็นงานที่คนอื่นกำลังตรวจ** — หน้าเว็บดึงรายการแค่ตอนเปิดครั้งเดียว ไม่มีปุ่มรีเฟรช
   (โค้ดฝั่งหลังบ้าน `get_qc_inspections` ไม่ได้กรองรายคนอยู่แล้ว — ข้อมูลแชร์ถูกต้อง เป็นปัญหาการแสดงผลล้วน ๆ)
2. **ไม่มีปุ่มลบ** — เวียงชัยเผลอสร้าง F-22 ซ้ำ 2 อัน ลบทิ้งไม่ได้
   (หลังบ้าน `delete_qc_inspection` มีอยู่แล้ว แต่ไม่มีปุ่มบนหน้าจอ)
3. **ปิดการตรวจแล้วเข้าไปดูผลไม่ได้** — `v3/qc.html:180` ถ้าสถานะ ≠ `pending` จะเด้งไปหน้าสรุปเสมอ
   ซึ่งโชว์เฉพาะข้อที่ไม่ผ่าน กลับเข้าฟอร์มไม่ได้อีกเลย
4. **กดตรวจอีกครั้งแล้วสร้างรายการใหม่** — ปุ่ม "ตรวจซ้ำรอบใหม่" (`v3/qc.html:239`) สร้างรอบที่ 2
   ตามที่ออกแบบไว้ แต่หน้ารายการแสดงทุกรอบเป็นแถวแยก → ดูเหมือน F-22 งอกหลายอัน
5. **ไม่รู้ว่าใครทำอะไร** — ช่อง "ผู้ตรวจสอบ" เป็นข้อความพิมพ์มือ ไม่ผูกกับคนที่ล็อกอิน
   และไม่มีบันทึกว่าใครติ๊กข้อไหน ใครปิดการตรวจ ใครลบ

## สิ่งที่จะสร้าง

### 1 · หน้ารายการจัดกลุ่มตามชิ้นงาน

หนึ่งแถว = หนึ่งชิ้นงาน (`ff_code`) แสดง **รอบล่าสุด**: สถานะ · รอบที่ n · วันที่ · ผู้เปิดการตรวจ

ถ้ามีมากกว่าหนึ่งรอบ → บรรทัด `ประวัติการตรวจ N รอบ ▾` กางออกได้ แต่ละรอบแสดง

```
รอบ 1 · 10 ก.ค. · เวียงชัย · ผ่าน 20 / ไม่ผ่าน 4 / N/A 2 · ปิดโดย เวียงชัย 10 ก.ค. 16:20
```

กดที่รอบใดก็เปิดรอบนั้นได้ · เรียงรอบใหม่สุดอยู่บน

**ปุ่ม 🔄 รีเฟรช** บนหัวรายการ + ดึงข้อมูลใหม่อัตโนมัติเมื่อผู้ใช้สลับกลับมาที่แท็บ
(`visibilitychange`) — ไม่ทำ realtime push เพราะต้องรื้อ backend และไม่คุ้ม

### 2 · เปิดรอบที่ปิดแล้วได้ครบ 26 ข้อ และแก้ไขได้

เปิดฟอร์มเดิมกลับมา พร้อมแถบสรุปสถานะค้างบนสุด แก้ผลข้อใดก็ได้
ปุ่มล่างเปลี่ยนเป็น "ปิดการตรวจอีกครั้ง" → เรียก `close_qc_inspection` คำนวณสถานะใหม่

ไม่ต้องมี action `reopen` แยก เพราะ `update_qc_result` ไม่ได้เช็คสถานะหัวอยู่แล้ว
— แค่หน้าเว็บเลิกบล็อกก็พอ

ปุ่ม "ตรวจซ้ำรอบใหม่" ยังอยู่ (คือกลไกสร้างประวัติ) แต่เพิ่ม modal ยืนยัน
`"จะสร้างรอบที่ 2 ของ F-22 ใหม่ ยืนยันไหม?"` กันกดพลาด

### 3 · ลบ → ถังขยะ 30 วัน

- `delete_qc_inspection` เปลี่ยนจากลบจริงเป็น **soft delete** (ประทับ `deleted_at` + `deleted_by`)
- `restore_qc_inspection` (ใหม่) — กู้คืน
- `get_qc_trash` (ใหม่) — รายการในถังขยะของโครงการ + เหลืออีกกี่วัน
- **ลบจริงอัตโนมัติ**: กวาดแบบ lazy ตอนมีคนเรียก `get_qc_inspections`
  (ลบแถวที่ `deleted_at` เก่ากว่า 30 วัน พร้อม `qc_results` ของมัน)
  เหตุผล: Cron Triggers ของโปรเจกต์นี้ปิดอยู่ (`cf-api/wrangler.toml` — Cloudflare
  ลงทะเบียน schedule ไม่ผ่านตั้งแต่ 2026-07-15) ผลลัพธ์จากมุมผู้ใช้เหมือนกัน
- UI: แถบ `🗑 ถังขยะ (n)` เปิดดูได้ แต่ละรายการบอก `ลบโดย X · เหลืออีก 27 วัน` + ปุ่มกู้คืน

**สิทธิ์**: พนักงานทุกคนที่เข้าหน้า QC ได้ ลบได้ (ถังขยะคือตาข่ายกันพลาด)
ไม่แตะ `authz.ts` — QC actions ยังอยู่ในกลุ่ม unmapped เหมือนเดิม เพื่อไม่ให้สิทธิ์ของคนที่ใช้อยู่เปลี่ยน

### 4 · บันทึกว่าใครทำอะไร (audit trail)

ชื่อคนทำมาจาก `params.__actor` ฝั่ง Worker (`cf-api/src/index.ts:87`) ซึ่งถอดจาก token ตอนล็อกอิน
→ **ปลอมไม่ได้** ห้ามเชื่อชื่อที่หน้าเว็บส่งมา

คอลัมน์ใหม่ (เพิ่มอย่างเดียว ไม่แก้ของเดิม ตาม deploy pattern ของโปรเจกต์):

| ตาราง | คอลัมน์ | ความหมาย |
|---|---|---|
| `qc_inspections` | `created_by` | ใครเปิดรอบตรวจ |
| | `closed_by`, `closed_at` | ใครกดสรุป & ปิด เมื่อไหร่ |
| | `deleted_by`, `deleted_at` | ใครทิ้งลงถังขยะ เมื่อไหร่ |
| `qc_results` | `checked_by`, `checked_at` | ใครติ๊กข้อนี้ เมื่อไหร่ |

จุดที่แสดง: แถวรายการ · ประวัติแต่ละรอบ · ใต้ปุ่มผ่าน/ไม่ผ่านรายข้อ (`✓ เวียงชัย · 10 ก.ค. 15:42`)
· ถังขยะ · PDF

ช่อง "ผู้ตรวจสอบ" ตอนเปิดการตรวจ เติมชื่อคนที่ล็อกอินให้อัตโนมัติ แต่ยังพิมพ์ทับได้ (เผื่อตรวจแทนกัน)

ข้อมูลเก่าที่ตรวจไปก่อน deploy จะแสดง `—` (ไม่มีการย้อนหลัง)

### 5 · ออกไฟล์ PDF

ใช้ระบบพิมพ์ของเบราว์เซอร์ (`window.print()` + `@media print`) ไม่ใช้ jsPDF
เหตุผล: jsPDF ต้องฝังฟอนต์ไทยเป็น MB และมักเพี้ยน (สระลอย) — พิมพ์ตรงใช้ฟอนต์ในเครื่อง ไทยถูกต้องแน่นอน
และ "บันทึกเป็น PDF" มีในทั้งมือถือและคอม ส่งเข้าไลน์กลุ่มได้ทันที

เนื้อในเอกสาร:
1. หัวกระดาษ — โครงการ · FF Code · รายการ · ตำแหน่ง · ช่าง · เลขที่แบบ · ผู้ตรวจ · วันที่ · รอบที่
2. ป้ายสถานะ + ผลรวม ผ่าน/ไม่ผ่าน/N-A
3. ตารางครบทุกข้อ: ลำดับ · รายการตรวจ · เกณฑ์ · ผล · ระดับ defect · หมายเหตุ · ผู้ตรวจข้อนั้น
4. **รูป defect** (ตามที่เจ้าของงานเคาะ) — เรียงท้ายตาราง ระบุว่าเป็นของข้อไหน
5. ท้ายเอกสาร — เปิดโดย / ปิดโดย / พิมพ์โดย + วันเวลา · ช่องเซ็นชื่อผู้ตรวจ + ผู้รับมอบ

## สิ่งที่จงใจไม่ทำ (YAGNI)

- realtime push / websocket — ปุ่มรีเฟรช + auto refresh ตอนสลับแท็บพอแล้ว
- action `reopen_qc_inspection` แยก — ไม่จำเป็น (ดู §2)
- ย้อนหลังใส่ชื่อผู้ทำให้ข้อมูลเก่า — เดาไม่ได้ ปล่อยเป็น `—`
- แก้ `authz.ts` map สิทธิ์ QC — เสี่ยงตัดสิทธิ์คนที่ใช้อยู่ แยกเป็นงาน RBAC sweep ต่างหาก
